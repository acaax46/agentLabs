# AgentLab 演示操作与口播脚本

适用场景：项目演示、黑客松答辩、产品录屏。按 2026-10-25 的工作台和代码编写，主线使用当前“对话”入口，剪辑后约 5–7 分钟；现场另留真实模型等待时间，时间标记是讲解安排，不是性能数据。

演示主线：**选择项目与模型 → 配置对话 → 上传订单 → 生成表格和图表 → 多轮修改 → 查看运行与费用**。可追加 API 集成和独立工具调用片段。

环境启动见[本地启动与 MVP 视频说明](local-start-and-mvp-video.md)，能力与验收边界见[实施现状](implementation-status.md)。本文是操作与台词，不代表已经执行了新一轮模型验收。

## 1. 上台前准备

以下准备在正式录屏前完成。主视频从已登录的工作台开始，初始化、构建镜像和录入密钥不用占演示时间。

| 准备项       | 操作与确认                                                                                                                    |
| ------------ | ----------------------------------------------------------------------------------------------------------------------------- |
| 本地环境     | 按启动说明运行 MongoDB、API 和前端；已构建 CPU 沙箱镜像，工作台执行能力可用。                                                 |
| 浏览器       | 打开 `http://127.0.0.1:5173`，建议窗口 1440×900、浏览器缩放 100%；关闭无关标签页和通知。                                      |
| 登录         | 使用已有演示账号；管理员可完成全部配置。账号来源见 [README](../README.md)，录屏不展示密码。                                   |
| 项目         | 准备“AgentLab 演示”项目并设为当前项目；以 CNY 为例，累计预算设为 10，每轮上限设为 2。两者是预算参数，不是任务报价或充值余额。 |
| 模型         | 准备状态为“已连接”、对当前项目可用，且实际预演过文件分析的模型。主线只选一种来源；平台供模或 BYOK 均可，按实际来源使用台词。  |

| 备用画面     | 另开[技术架构图](diagrams/agentlab-platform.png)，供等待或技术说明时切换。                                                    |

主录屏中不打开 `.env.dev`、供应商凭据、完整 API Key、浏览器网络请求头或终端变量列表。连接配置和 API Key 保存操作放在录屏之外完成。

### 演示数据与人工核对值

`demo/orders.csv` 内容如下：

```csv
order_id,region,amount
A001,east,12.50
A002,west,20.00
A003,east,3.25
```

| 核对项                 | 根据输入计算的期望值 |
| ---------------------- | -------------------: |
| 订单行数               |                    3 |
| east 合计              |                15.75 |
| west 合计              |                20.00 |
| 总金额                 |                35.75 |
| 追问后的 east 翻倍金额 |                31.50 |
| 追问后的 west 翻倍金额 |                40.00 |

这些是输入数据的人工校验值，不是预先生成的模型结果。金额单位未在源文件中声明，口播使用“金额”；它与项目计费币种 CNY 是两件事。表格行顺序、显示为 `20` 或 `20.00` 不影响数值核对。

每段按“操作 → 台词 → 画面核对”执行。需要等待结果的段落，只有实际出现对应状态和产物后才使用完成台词。

| 0:55–1:25 | 配置对话   | Agent、模型、CPU 规格、每轮上限  |

### 第 1 段：开场，说明本次任务

**操作**

1. 停在工作台“对话”配置页，保留侧栏和当前项目选择器。
2. 先不要点击“进入对话”。

**口播**

> 大家好，下面演示 AgentLab。它面向开发者和团队，把模型调用、工具执行、文件产物和费用核对放在同一个工作台里，也提供可以接入应用的 API。今天用一份三行的订单文件，完成汇总、绘图，再通过追问修改结果。

**画面核对**：能读到 AgentLab 字标、“对话”和当前项目名称。

### 第 2 段：展示项目边界和模型来源

**操作**

1. 进入“项目”，打开“AgentLab 演示”，确认它是当前项目。
2. 指向“项目累计预算”、预占和可用预算；不把预算称为余额。
3. 打开“连接”，只展示连接名称、来源、可用项目与“已连接”状态。

**口播**

> 每次执行都归属于一个项目，运行记录、文件和费用也按项目查询。这里的累计预算用来约束任务开销，不是充值余额。模型可以选择平台供模，也可以使用团队自己的供应商账户。

随后根据本次实际选择，补充一句：

- 平台供模：**“这次使用平台供模，模型费用按本次运行锁定的价格规则计量。”**
- BYOK：**“这次使用 BYOK，模型费用由自己的供应商账户承担；平台的执行和工具用量单独核对。”**

**画面核对**：项目、币种和连接来源一致；“已连接”只说明连接验证通过，不朗读成所有模型都已通过任务质量验证。

### 第 3 段：配置一次对话

**操作**

1. 返回侧栏“对话”。
2. “选择 Agent”设为“文件分析 Agent”，模型选刚才确认的可用项。
3. 在“沙箱规格”选择可用 CPU 规格，例如 `cpu-2-4`。
4. 展开“运行偏好与费用上限”，将“每轮费用上限”设为 `2`，确认币种为 CNY。
5. 保持“执行引擎”为 `AgentLab 内置循环`，点击“进入对话”。

**口播**

> 开始前，我选择文件分析 Agent、模型和执行规格，再设置每一轮的费用上限。进入对话本身不收费，发送消息后才按上限预占预算。本次选择的 CPU 规格和单价都可以在这里看到。

**画面核对**：出现“沙箱配置已就绪”；底部显示每轮上限和“发送即预占”。已发布版本与冻结信息稍后在 Run 详情展示。

### 第 4 段：上传文件并提交首轮任务

**操作**

1. 点击输入框旁的“添加文件”，选择仓库中的 `demo/orders.csv`。
2. 等上传完成，确认输入区出现 `orders.csv` 附件。
3. 粘贴下方指令，停留片刻供观众阅读，再点击“发送消息”。只发送一次。

**可直接复制的首轮指令**

```text
分析附件 orders.csv。请先按 region 汇总 amount，生成 summary.csv，列名为 region、total_amount；优先使用结构化文件处理工具完成汇总。再使用代码工具根据汇总结果生成 chart.png，图表坐标轴用英文标签。最后生成 report.md，用中文写明订单行数、各地区金额、总金额和校验过程。输入文件只读，金额保留两位小数；只列出实际生成的文件。
```

**口播**

> 我上传一份小型订单表，要求按地区汇总金额，输出汇总表、图表和一份说明报告。输入和输出要求写清楚后，平台会为这一轮创建 Run，按固定版本、模型和费用上限执行。

**画面核对**：消息和文件出现在对话中，进入准备或运行状态；可从进度里的“查看完整运行记录”取得本轮 Run ID，供后面的费用核对和 API 片段使用。

### 第 5 段：展示执行进度

**操作**

1. 展开本轮回复上方的进度折叠项，展示实际收到的事件。
2. 指向模型、工具或沙箱事件，以及“停止生成”入口；正常主线不点击停止。
3. 若任务已经完成，直接展示保留下来的事件记录，不把历史事件说成正在发生。

**口播**

> 这里可以看到公开回复和执行进度。展开后能核对模型请求、工具处理和沙箱执行的实际事件，也可以主动停止本轮。停止会阻止后续执行，已经发生的调用和费用仍然保留。

**画面核对**：展示真实事件，不朗读不存在的工具调用；回复增量不代表展示模型内部推理。等待时间较长时可切到架构图解释，后台 Run 保持运行。

### 第 6 段：预览产物并核对数据

**操作**

1. 等本轮显示“执行完成”。
2. 点击 `summary.csv` 产物卡片，在预览侧栏核对 east 和 west 的金额。
3. 点击 `chart.png`，展示图表；再查看 `report.md` 的行数、总金额和计算说明。
4. 展示一个文件的下载入口；需要演示实际领取时，下载 CSV 后打开核对。

**口播：仅在结果核对通过后朗读**

> 这一轮已经完成，文件可以直接预览和下载。这里 east 汇总为 15.75，west 为 20，总金额是 35.75，能从三行输入逐项回算。图表和报告也作为真实文件保存，并关联到本次运行。

**画面核对**：实际产物与人工校验值一致；报告里说生成了某个文件时，列表中也确实有该文件。若文件名有变化，按真实名称操作和口播；缺少产物或数值不符时先处理，不使用上面的成功台词。

### 第 7 段：不重新上传，继续修改结果

**操作**

1. 关闭产物预览，在同一个对话中继续输入。
2. 不重新上传 `orders.csv`，发送下方追问。
3. 等待本轮完成，打开 `summary_doubled.csv`，核对新增列。

**可直接复制的追问指令**

```text
继续使用上一轮的 summary.csv，不重新上传原始文件。保留 region、total_amount 两列，新增 double_amount 列，值为 total_amount 的两倍，输出为 summary_doubled.csv。不要覆盖上一轮文件。请用中文简要说明修改，并核对新列数值。
```

**口播：发送时**

> 接下来继续修改刚才的结果。我没有重新上传原始订单，而是引用上一轮生成的汇总文件，让 Agent 增加一列翻倍金额。每轮都有独立 Run 和费用上限，可以分别追踪。

**口播：产物核对通过后**

> 新文件已经生成，原始汇总列仍然保留，新增列分别是 31.50 和 40。这样可以在同一段对话里逐步完善结果。

**画面核对**：第二轮对应新 Run；第一轮产物仍可查看。跨轮恢复的是消息和文件，不能说成容器进程、内存或已安装依赖持续保留。

### 第 8 段：刷新并恢复历史

**操作**

1. 两轮均结束后刷新页面。
2. 等历史加载完成，确认两轮消息和产物入口恢复。
3. 若需要从历史列表选择，点击本次对话，不新建对话。

**口播**

> 刷新后，消息和文件还能恢复，因为它们保存在后端。沙箱只在每轮运行时启动并回收，等待下一条消息时，不会为了保留聊天历史持续占用容器。

**画面核对**：当前项目和对话正确，历史确实恢复。未完整加载时先等待，不口播成历史丢失或已经恢复。

### 第 9 段：展开运行证据与费用

**操作**

1. 展开**第一轮**进度，点击“查看完整运行记录”。
2. 在 Run 详情展示 Run ID、Agent 发布版本、模型来源、状态和“运行与费用”。
3. 切换“执行时间线”和“工具调用树”，按实际记录说明本次使用的工具。
4. 点击“核对本次用量与账本”，确认页面保留当前 Run 筛选。
5. 展示模型、工具、托管执行、沙箱等实际存在的用量行，再查看“只追加账本”。

**口播**

> 从对话可以打开完整 Run，核对发布版本、模型来源、工具调用和产物。文件汇总与代码执行各自留下记录，其中代码进入无网 Docker 沙箱。这里按本次 Run 查看分项用量，预算预占、实际结算和剩余预占释放也能关联起来。

再根据实际记录补充：

- 两类工具都出现：**“这里记录了 files.transform 的结构化处理，以及 code.execute 的代码执行。”**
- 只出现一种工具：**“这次实际使用的是这里记录的工具，调用过程以 Run 记录为准。”**
- BYOK：**“模型费用由客户的供应商账户承担，平台费用与它分开展示。”**

**费用台词**

> 这里显示的平台结算依据是本次运行的用量证据和锁定价格，不代表已经核对供应商最终账单。未知项保留未知，存储当前只披露用量，不单独形成已结算费用。

**画面核对**：费用带币种和结算状态；不预报一个固定任务价格，不把预占说成已扣费。停止、失败和未知结果按实际状态说明。

### 第 10 段：用架构图收尾

**操作**

1. 切到提前打开的[技术架构图](diagrams/agentlab-platform.png)。
2. 顺序指向平台 API、MongoDB、Worker、模型网关和 Docker 沙箱。
3. 若时间紧，只停留在 README 的架构图。

**口播**

> 这条链路由 Go API 受理，MongoDB 保存任务、事件和账本，Worker 领取租约后编排执行。模型凭据保留在容器执行域外，代码在无网沙箱中运行。当前交付是可复核的本机 MVP，已经覆盖对话、产物和运行费用查询；云端多租户、商业支付和 SLA 仍是后续工作。

## 3. 可选片段 A：API 集成（约 1–2 分钟，另留执行等待时间）

目标：用 API Key 调用同一项目中的首轮 AgentVersion、模型和输入文件，并在工作台看到来源为 API 的新 Run。这个片段会再产生一次真实运行。

### 录制前准备

1. 在“API 密钥”点击“创建 API Key”，名称填写 `demo-api`。
2. 选择“提交运行”“读取运行与事件”“读取产物”“读取用量”这些本片段需要的 scope；有效期可选 30 天，月度费用上限设为 `2 CNY`。
3. 在不录屏时安全保存完整密钥，完成“我已保存”。主录屏只展示密钥名称、前缀、范围和期限。
4. 记下主演示第一轮的 Run ID。输入文件必须仍在保留期内，密钥必须属于同一项目，模型连接仍须有效。

### 操作与台词

**操作**：打开准备好的 PowerShell，从项目根目录执行。第一块是场外准备；不在录屏中显示密钥输入、变量内容或授权请求头。

```powershell
$demoApi = 'http://127.0.0.1:8787/v1'
$demoSecret = Read-Host '输入一次性演示 API Key（隐藏）' -AsSecureString
$demoHeaders = @{
  Authorization = 'Bearer ' + [System.Net.NetworkCredential]::new('', $demoSecret).Password
}
$demoSourceRunId = Read-Host '输入主演示第一轮的 Run ID'
$demoSource = Invoke-RestMethod -Uri "$demoApi/runs/$demoSourceRunId" -Headers $demoHeaders

# 同一次提交意图只初始化一次；超时后保留该值，不生成新键盲目重发。
$demoIdempotencyKey = 'demo-run-' + [Guid]::NewGuid().ToString('N')
$demoWriteHeaders = $demoHeaders + @{ 'Idempotency-Key' = $demoIdempotencyKey }
$demoBody = @{
  agentVersionId = $demoSource.agent.versionId
  modelConnectionId = $demoSource.model.connectionId
  model = $demoSource.model.model
  input = @{
    instruction = $demoSource.instruction
    artifactIds = @($demoSource.inputArtifactIds)
  }
  limits = @{ maxCostMicros = '2000000'; currency = $demoSource.currency }
}
if ($demoSource.resources) {
  $demoBody.resourceProfile = $demoSource.resources.id
}
$demoBodyJson = $demoBody | ConvertTo-Json -Depth 8
```

**录制画面**：展示提交命令与不含秘密的返回字段。

```powershell
$demoRun = Invoke-RestMethod -Method Post -Uri "$demoApi/runs" `
  -Headers $demoWriteHeaders -ContentType 'application/json' -Body $demoBodyJson
$demoRun | Select-Object id, status, agent
```

**口播**

> 这次换成应用调用：API Key 绑定同一个项目和明确的操作范围，请求继续使用刚才的 Agent 版本、模型和文件。服务以 202 接受运行并返回 Run ID，应用可以继续查询状态和订阅事件。

**可选的幂等演示**：保持请求体和请求头不变，再发一次同样的请求。

```powershell
$demoReplay = Invoke-RestMethod -Method Post -Uri "$demoApi/runs" `
  -Headers $demoWriteHeaders -ContentType 'application/json' -Body $demoBodyJson
$demoReplay.id -eq $demoRun.id
```

**口播：仅在返回 `True` 后朗读**

> 使用同一个幂等键重复提交，返回的是同一个 Run，不会再创建一份任务或重复预占预算。

**操作**：回到工作台“运行”，将“调用来源”切到“API”，打开返回的 Run ID。若还在运行，展示真实状态；只有实际完成后才继续展示产物和结算。

**口播**

> 回到工作台，可以看到这条调用来自 API。人的工作台和应用的接口调用，共用同一套运行、权限和费用记录。

**收尾**：演示结束后，在“API 密钥”撤销 `demo-api`，清除本次终端里的凭据变量；保留 Run 和产物作为演示证据。

```powershell
Remove-Variable demoSecret, demoHeaders, demoWriteHeaders -ErrorAction SilentlyContinue
```

## 4. 可选片段 B：独立工具调用（约 1 分钟）

目标：展示同一个文件处理工具可以直接使用，无需模型参与这一段处理。实际价格以页面当前版本为准，不把开发预设的零单价宣称为永久免费。

**操作**

1. 进入“工具”，找到 `files.transform@1.0.0`，点击“调试”。
2. 在“允许工具读取的文件”中只勾选本次 `orders.csv`；若没有可用输入，用“上传工具输入文件”重新上传一次。
3. 将“工具输入 JSON”替换为下方内容，核对当前价格、预占和副作用说明，勾选确认后提交。

## 5. 现场异常时怎么操作、怎么说

| 现场情况             | 操作                                                                                 | 可用台词                                                                         |
| -------------------- | ------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------- |
| 模型或容器仍在处理   | 保留当前 Run，展开事件；可切到架构图解释，随后回到原 Run。                           | “任务还在执行，我们先看运行结构，完成后回到同一条记录核对结果。”                 |
| 发送后网络中断       | 先查对话历史和运行列表，确认是否已受理；不要再次新建同样的任务。                     | “先核对刚才是否已经受理，避免把网络中断变成重复执行。”                           |
| 执行能力不可用       | 展示原因并检查 Docker、镜像与规格；不继续声称已执行。                                | “当前执行环境未就绪，平台会拒绝代码执行，需要先恢复环境。”                       |
| 模型连接或预算不可用 | 查看连接可用项目、模型状态和剩余预算；重新提交前先解决原因。                         | “提交前会检查连接和预算，条件不满足时会明确拒绝。”                               |
| 产物缺失或数值不符   | 保留本轮记录，打开工具结果和输入核对；需要重跑时明确这是新的一次运行。               | “这次结果还没有通过输入数据核对，先查看执行记录和产物，再决定如何修正。”         |
| 显示“结果待核对”     | 保留 Run ID、事件和预占，结束本次成功路径讲解，等待证据核对。                        | “这一轮存在已派发但结果未确认的操作，预占保持冻结，平台不会自动重发或承诺退款。” |
| 主动展示停止         | 单独发起一个已预演的片段，点“停止生成”，阅读说明，再点“确认停止”；等待真实状态更新。 | “停止会阻止后续执行，已经发生的调用、费用和外部副作用仍然保留。”                 |

如果切到之前的真实成功 Run，明确说“下面查看预演时保存的运行记录”，同时保留其时间和 Run ID。录屏可以剪短无变化的等待，但保留本次提交、至少一个进行中状态和最终状态。

## 6. 只有 3 分钟时如何裁剪

保留第 1、3、4、6、9 段：开场说明目标，项目和连接提前配好；选择 Agent 并提交，展示一个汇总表和一张图，最后核对 Run 与费用。省去多轮追问、刷新、架构细讲和可选 API/工具片段；真实等待较长时使用明确标注的加速剪辑。

可用的精简收尾台词：

> 刚才完成了从订单文件到分析产物的闭环，输入、工具调用、输出和费用都能关联到具体 Run。工作台用于调试和核对，同一能力也可以通过项目 API Key 接入应用。当前演示范围是本机 MVP。
